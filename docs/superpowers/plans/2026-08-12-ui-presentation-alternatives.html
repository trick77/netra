Three Ways to Read a Host

The charts are not the problem. The problem is that the host page is twelve cards of equal weight in a two-column flow, so nothing is more important than anything else and the reader does the triage netra should have already done. Same host, same palette, same data in all three — only the presentation changes.

A

Triage first

One question governs the page: does this host need me right now? What is wrong leads, at full size, with the time it started. Everything healthy collapses into a strip of six numbers and named folds. The breakdowns still exist — they are one click away and stay closed on a healthy host, which is most hosts most of the time.

Fixes
Hierarchy. A healthy host is six numbers and silence; a sick one puts the reason at the top in words, with a timestamp.
Costs
Browsing gets slower — reading a fan you have no complaint about is now a click. Needs every card to have a one-line summary worth collapsing to.
Best if
You open netra because something is wrong.
B

The console

No cards at all. Rules instead of boxes, one monospace grid, everything on one screen with no tabs and no folds. This is the density of htop or zpool status — the tools this data actually comes from — and it treats the reader as someone who already knows what tcp_tw is. Sparklines stay; they are the one thing a terminal cannot do.

Fixes
Density and scanning. Everything is on one screen with no navigation at all, and the columns line up so values compare down the page.
Costs
Unforgiving to anyone who does not already know the vocabulary. Long hosts scroll a lot. Little room for explanation when a value is absent.
Best if
netra is for you and people like you, not for a dashboard on a wall.
C

Rail and canvas

The fleet never leaves the screen. A persistent left rail lists hosts with their one worst fact, so moving between machines is a click and not a round trip through an index — and the eight tabs collapse into a sticky section nav over one scrolling canvas, so the page has one scroll position instead of eight.

Costs

Best if

What I would change in any of them

  • Kill the uppercase card headings. Twelve LETTER-SPACED CAPS down a page read as twelve equally loud shouts. Sentence case in the ink colour, or no heading at all where the content names itself.
  • Stop boxing everything. Every card has a border, a radius and a shadow, so the chrome outweighs the content. A rule and whitespace separate sections just as well and cost nothing.
  • Give the eight tabs an order that means something. Overview, Graphs, Containers, Filesystems, Network, Packages, Units, Events is the order the code was written in, not the order anyone needs them.
  • One number per card, not five. The Inventory card says 13 containers, 12 units, 6 filesystems — three counts nobody acts on, occupying the same space as the thing that is actually broken.
