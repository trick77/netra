Stage 1C PR 1 — collector contract and per-core CPU

For agentic workers: REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

Goal: Change the collector contract so a collector returns its contribution instead of mutating a shared sample, carry per-entity rows on the wire and through the ring buffer, and prove it end to end with a per-core CPU collector writing cpu_core_samples.

Architecture: Collect(ctx) (*Result, error) replaces Collect(ctx, *HostSample) error. The agent merges results from collectors that succeeded with proto.Merge and discards failures whole, which closes the partial-write hole where a collector that fails midway leaves its already-written fields looking like measurements. A buffered ring entry becomes a whole scrape — host row plus per-family rows — so an outage cannot replay host rows while dropping the per-core rows measured alongside them. Flush batching moves from counting samples to counting rows, because a batch of 2000 samples that each carry 64 cores would exceed the hub's body limit.

Tech Stack: Go 1.x, protobuf (google.golang.org/protobuf), pgx v5, TimescaleDB, buf for codegen.

Global Constraints

  • Spec: docs/superpowers/specs/2026-08-09-stage1c-collectors-design.md.
  • Scrape interval is a fixed 60s const (config.ScrapeInterval). Never make it configurable; never add a per-host cadence.
  • All schema changes are edited into internal/hub/store/migrations/0001_init.sql in place. There is no 0002. 0001 must stay re-runnable (IF NOT EXISTS, guarded SELECTs).
  • An unset proto field means the subsystem is absent (spec §5.1 rule 3). Never write a zero where nothing was measured.
  • IngestResponse field 4 stays reserved. Never reuse it.
  • Every collector: fixture-based tests with checked-in /proc trees, never reads the host it is tested on, and never prevents the agent from starting.
  • Commit as trick77@users.noreply.github.com. Feature branch, never push to master.
  • Run tests with the project venv/Go toolchain locally. Integration tests need NETRA_TEST_DSN=postgres://netra:netra@127.0.0.1:5432/netra_test and the netra-test-db container running.

Create internal/agent/collector/result.go:

package collector

import netrav1 "github.com/trick77/netra/internal/gen/netra/v1"

// Result is one collector's contribution to a scrape.
//
// A collector fills only what it owns and leaves everything else nil. The
// agent merges the results of collectors that succeeded and discards the rest
// whole, so a collector that fails part-way through contributes nothing rather
// than leaving half its fields behind.
type Result struct {
	// Host is this collector's share of the wide per-host row. Fields it does
	// not own stay unset, and the agent merges only the set ones.
	Host *netrav1.HostSample

	// Cores is one row per CPU core. Later 1C PRs add a slice per family
	// alongside this one.
	Cores []*netrav1.CpuCoreSample
}

// Collect implements Collector.
func (c *CPU) Collect(_ context.Context) (*Result, error) {
	cur, err := c.read()
	if err != nil {
		return nil, err
	}

	prev := c.prev
	c.prev = &cur

	if prev == nil {
		// No baseline yet: report nothing rather than invent a value.
		return &Result{}, nil
	}

	totalDelta := cur.total() - prev.total()
	if cur.total() < prev.total() || totalDelta == 0 {
		return &Result{}, nil
	}

	pct := func(a, b uint64) *float64 {
		if a < b {
			return nil
		}
		v := float64(a-b) / float64(totalDelta) * 100
		return &v
	}

	if cur.busy() < prev.busy() {
		return &Result{}, nil
	}
	totalPct := float64(cur.busy()-prev.busy()) / float64(totalDelta) * 100

	return &Result{Host: &netrav1.HostSample{
		CpuTotal:  &totalPct,
		CpuUser:   pct(cur.user, prev.user),
		CpuSystem: pct(cur.system, prev.system),
		CpuIowait: pct(cur.iowait, prev.iowait),
		CpuSteal:  pct(cur.steal, prev.steal),
		CpuIdle:   pct(cur.idle, prev.idle),
	}}, nil
}

Note the distinction the tests must preserve: nil, err on failure; &Result{}, nil when there is simply nothing to report yet. "No baseline" is not an error.

Task 5: Bound a flush by rows, not by samples

maxBatchSamples = 2000 exists so a request stays inside the hub's maxBodyBytes = 4 << 20. That arithmetic assumed one narrow row per sample. A 64-core host draining 2000 buffered scrapes now sends 2000 host rows and 128,000 core rows in one body, which exceeds the limit and produces the 413-forever failure maxBatchSamples was written to prevent.

// samples stopped being a proxy for body size the moment a scrape started
// carrying per-entity rows: 2000 scrapes from a 64-core host is 128k core

// maxBatchRows caps the TOTAL rows in one flush -- host samples plus every
// per-entity row riding with them -- so the encoded body stays inside the
// hub's maxBodyBytes (4MB). Counting host samples alone was a valid proxy
// only while a scrape was one narrow row; a 64-core host carries 65 rows per
// scrape, so the sample count no longer says anything about body size.
//
// 20000 rows at a generous 100 bytes each is ~2MB, half the cap, leaving room
// for the metadata block and for families added by later 1C PRs. AckThrough
// is prefix-based and seq is monotonic, so draining a prefix is exactly as
// safe as draining the whole ring.
const maxBatchRows = 20000

and drain by accumulating rows:

	rows := 0
	for _, e := range pending {
		next := 1 + len(e.Scrape.Cores)
		if rows > 0 && rows+next > maxBatchRows {
			break
		}
		entries = append(entries, e)
		rows += next
	}

The rows > 0 guard matters: a single scrape whose rows exceed the cap on its own must still be sent, or it blocks the ring forever.

  • Step 4: Re-derive the memory bound

maxBufferSlots = 10000 and capacityFor were written when a slot was one narrow row; the spec (§2) requires this be settled here rather than discovered during an outage on the largest host. Update the reasoning in the comment and leave the value with a stated basis:

// maxBufferSlots caps the ring's capacity in entries, independently of the
// window/interval arithmetic that sizes it. A slot is now a whole scrape --
// the host row plus every per-entity row measured with it -- so a slot is
// both larger and variable: a 64-core host buffers ~65 rows per slot where a
// 1-core VPS buffers 2.
//
// The window arithmetic still bounds the slot COUNT correctly (360 at the 6h
// maximum, at the fixed 60s cadence). Worst case is therefore ~360 * 65 =
// ~23k rows, a few MB -- acceptable on a host the agent is meant to be a
// negligible tenant of. This constant stays a standing guard on the
// invariant rather than a limit reached in practice; revisit it if a family
// arrives whose row count per scrape is unbounded (containers, processes).
const maxBufferSlots = 10000

capacityFor itself needs no change: it sizes the ring so capacity * interval stays inside the window, which is still exactly what it should do.

// PerCoreCPU reports per-core busy percentage from /proc/stat's cpuN lines.
//
// Separate from CPU on purpose: CPU owns the aggregate line and writes scalar
// host fields, this owns the per-core lines and produces one row per core.
// Splitting them keeps each collector's failure independent -- an unparseable
// cpuN line must not cost the host its aggregate utilisation.
type PerCoreCPU struct {
	procRoot string
	interval time.Duration
	prev     map[uint32]cpuTimes
}

func NewPerCoreCPU(procRoot string, interval time.Duration) *PerCoreCPU {
	return &PerCoreCPU{procRoot: procRoot, interval: interval}
}

func (p *PerCoreCPU) Name() string            { return "percpu" }
func (p *PerCoreCPU) Interval() time.Duration { return p.interval }

// SetProcRootForTest repoints the collector at another fixture tree so a test
// can simulate the passage of time between two scrapes.
func (p *PerCoreCPU) SetProcRootForTest(root string) { p.procRoot = root }

func (p *PerCoreCPU) Collect(_ context.Context) (*Result, error) {
	cur, err := p.read()
	if err != nil {
		return nil, err
	}

	prev := p.prev
	p.prev = cur

	if prev == nil {
		return &Result{}, nil
	}

	ts := time.Now().UnixMilli()
	cores := make([]*netrav1.CpuCoreSample, 0, len(cur))

	ids := make([]uint32, 0, len(cur))
	for id := range cur {
		ids = append(ids, id)
	}
	// Sorted so the rows are deterministic; the hub keys on (host, ts, core)
	// and does not care, but a stable order makes tests and logs readable.
	slices.Sort(ids)

	for _, id := range ids {
		c := cur[id]
		q, ok := prev[id]
		if !ok {
			// A core that appeared this scrape has no baseline yet.
			continue
		}
		totalDelta := c.total() - q.total()
		if c.total() < q.total() || totalDelta == 0 || c.busy() < q.busy() {
			// Reset, or no movement: no meaningful percentage. Emit no row
			// rather than a zero, which would read as a genuinely idle core.
			continue
		}
		busy := float64(c.busy()-q.busy()) / float64(totalDelta) * 100
		cores = append(cores, &netrav1.CpuCoreSample{TsMs: ts, Core: id, Busy: &busy})
	}

	return &Result{Cores: cores}, nil
}

read parses lines matching cpuN (reusing the unexported cpuTimes type and its total()/busy() methods from cpu.go, same package) into a map[uint32]cpuTimes, skipping the bare cpu aggregate line. Imports needed beyond the existing set: slices for the deterministic ordering.

// InsertCpuCoreSamples writes one row per core. ON CONFLICT DO NOTHING for the
// same reason host_samples has it: a replayed batch re-sends rows the hub
// already stored, and a duplicate must be absorbed rather than failing the
// flush and pinning the agent's ring buffer.
func (s *Store) InsertCpuCoreSamples(ctx context.Context, hostID int32, rows []*netrav1.CpuCoreSample) (int64, error) {
	if len(rows) == 0 {
		return 0, nil
	}

	const stmt = `
		INSERT INTO cpu_core_samples (host_id, ts, core, busy)
		VALUES ($1, $2, $3, $4)
		ON CONFLICT (host_id, ts, core) DO NOTHING`

	batch := &pgx.Batch{}
	for _, r := range rows {
		// r.Busy is passed as *float64 on purpose: nil becomes SQL NULL,
		// which is "not computable this scrape" -- a different fact from a
		// core that was genuinely 0% busy.
		batch.Queue(stmt, hostID,
			time.UnixMilli(r.GetTsMs()).UTC(),
			int32(r.GetCore()),
			r.Busy)
	}

	results := s.pool.SendBatch(ctx, batch)
	defer func() { _ = results.Close() }()

	var inserted int64
	for range rows {
		tag, err := results.Exec()
		if err != nil {
			return 0, fmt.Errorf("insert cpu core sample: %w", err)
		}
		inserted += tag.RowsAffected()
	}

	return inserted, nil
}

This mirrors InsertHostSamples exactly — pgx.Batch, SendBatch, then one results.Exec() per queued row totalling RowsAffected. There is no shared batch helper in this package; do not invent one for a single caller.
