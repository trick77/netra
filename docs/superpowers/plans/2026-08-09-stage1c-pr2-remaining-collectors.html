// Every dimension carries a surrogate id AND its natural key, with the natural
// key unique per host. Hypertables reference the id only, so renaming the thing
// on the host touches one dimension row and no history (spec 5.2).
func TestIntegrationGroup2DimensionsHaveSurrogateAndNaturalKeys(t *testing.T) {
	ctx := context.Background()
	s := store.OpenTest(t)
	if err := s.Migrate(ctx); err != nil {
		t.Fatalf("Migrate: %v", err)
	}

	for _, d := range []struct{ table, natural string }{
		{"containers", "container_key"},
		{"filesystems", "label"},
		{"devices", "device"},
		{"systemd_units", "unit_name"},
	} {
		var hasID bool
		if err := s.Pool().QueryRow(ctx, `
			SELECT EXISTS (
				SELECT 1 FROM information_schema.columns
				 WHERE table_name = $1 AND column_name = 'id')`, d.table).Scan(&hasID); err != nil {
			t.Fatalf("%s id lookup: %v", d.table, err)
		}
		if !hasID {
			t.Errorf("%s has no surrogate id", d.table)
		}

		// The natural key must be unique WITHIN a host, not globally: two hosts
		// both having an "sda" is normal.
		var unique bool
		if err := s.Pool().QueryRow(ctx, `
			SELECT EXISTS (
				SELECT 1 FROM pg_indexes
				 WHERE tablename = $1 AND indexdef LIKE '%UNIQUE%'
				   AND indexdef LIKE '%host_id%' AND indexdef LIKE '%' || $2 || '%')`,
			d.table, d.natural).Scan(&unique); err != nil {
			t.Fatalf("%s unique lookup: %v", d.table, err)
		}
		if !unique {
			t.Errorf("%s has no UNIQUE (host_id, %s); the same natural key could be inserted twice", d.table, d.natural)
		}
	}
}

Tasks 4-15: the collectors

Every collector follows the same shape, established in PR 1: Collect(ctx) (*Result, error), nil, err on failure, &Result{}, nil when there is nothing to report yet, fixtures under testdata/, registered in cmd/netra-agent/main.go, and one commit per collector.

Each task below is: write the fixture, write the failing test, implement, run, commit. The steps are not restated per collector — what differs is the trap each one has to avoid, which is what the notes below are for.

Task 4: Disk I/O (/proc/diskstats)

Rows: device, read_bytes, write_bytes, read_ops, write_ops, io_util_pct, r_await_ms, w_await_ms, weighted_io_pct.

Trap: counter resets. Every column is a rate derived from a monotonic counter that resets on reboot. Only the agent holds the previous reading, so only the agent can notice. A reset emits no row at all — not a zero, not a negative, not a spike. Same reset test as TestPerCoreCPUSkipsCoresMissingFromTheCurrentRead in shape.

Sector counts are 512-byte units regardless of the device's logical block size; multiply by 512 for bytes. Filter partitions (sda1) and keep whole devices (sda, nvme0n1) — a partition's I/O is already counted in its parent, so keeping both double-counts the host's throughput.

Task 5: Sensors (/sys/class/hwmon)

Rows: chip, label, temp. Dimension: sensors (host_id, chip, label).

Trap: identity. The key is chip_name + label, never hwmonN — the N is allocation-order dependent and changes across reboots, so a hwmon3 key silently reattributes one chip's history to another. Read name from the hwmon directory and tempN_label for each input.

Per-read deadline from NETRA_SENSORS_TIMEOUT: a wedged driver blocks a read() on sysfs indefinitely and would stall the whole scrape loop. Use a preference list for which sensors matter, not hottest-wins — hottest-wins reports a different physical sensor from one minute to the next.

Task 6: mdraid (sysfs)

Writes events, not a hypertable. An array is clean for weeks; a 60s series saying so is the same near-constant waste that keeps systemd out of §5.3. Only the transition is worth storing.

Trap: emitting on every scrape. The collector must hold the last known state per array and emit an event only when it changes. A first sighting emits one event establishing the baseline; identical subsequent readings emit nothing.

Task 7: Agent self-telemetry

Fills the remaining agent_samples columns: uptime_s, rss_bytes, goroutines, post_failures_total.

Trap: two different uptimes. agent_samples.uptime_s is the agent process; host_samples.uptime_s is the host. An agent uptime reset with host uptime unchanged means the agent restarted alone — which also means its ring buffer was lost. Conflating them hides crash-looping behind a healthy host. Write a test asserting the two differ for a process younger than its host.

Task 8: Network (/proc/net/dev)

Rows: iface, rx_bytes, tx_bytes, rx_errs, tx_errs. Needs network_mode: host.

Filter lo, veth*, docker0, br-* and tunnels — without network_mode: host the agent sees only its own namespace and should report the capability as unavailable rather than reporting the container's interfaces as the host's.

Task 9: Addresses (netlink)

Writes no samples. Populates host_addresses and flips metadata_hash so the hub re-asks for metadata.

Trap: the agent must not classify. It reports raw addresses; the hub derives scope (loopback/private/public) from the address, so the classification is one implementation that can be corrected without redeploying agents. Interface names are the join key with net_samples.iface — they must match exactly what the network collector reports.

Task 10: Containers (cgroup v2 + Docker socket)

Trap: page cache counted as memory. Raw memory.current includes the page cache, so a container that has merely read files looks like it is consuming that memory. Subtract cache and inactive_file — without it every container over-reports, and the number an operator would act on is wrong.

Identity is compose project + service (container_key), falling back to container name. The Docker socket is metadata only — names and images — never the metrics; cgroup v2 provides those and does not require the socket.

Task 11: Filesystems (statfs)

Trap: bind mounts double-count. Dedup by st_dev: the same filesystem mounted twice must produce one row, or a host's total disk usage is overstated by however many bind mounts it has.

Per-filesystem I/O needs the st_dev → block device mapping. Where that mapping fails, the value is NULL, not zero — "we could not attribute I/O to this filesystem" is not "this filesystem did no I/O".

Task 12: systemd (D-Bus)

Events, not samples, for the same reason as mdraid. A numeric summary (services_total, services_failed) rides on host_samples, so this collector returns both a Host contribution and events.

Task 13: Packages (dpkg/apk)

Parse on mtime change with a daily floor: the package DB is large and changes rarely, so re-parsing every 60s is pure waste. rpm reports an unsupported-format capability rather than failing — a RHEL host is not broken, it is unsupported, and those are different facts.

Task 14: SMART (smartctl)

1h interval — the only collector besides packages permitted a non-default one, because it writes its own table and contributes nothing to host_samples. Missing device access reports a capability, not a failure.

Trap: the attribute set varies per drive model, which is why smart_attributes is generic (attr_id, raw, normalized) rather than a column per attribute.

Task 15: Processes (pid: host)

Trap: recycled PIDs. utime+stime deltas must be keyed on (pid, starttime), not pid alone. A recycled PID otherwise produces a garbage spike — the new process's total CPU minus the old one's, attributed to whatever the new process is called.

Aggregate by name; report top-10-by-CPU ∪ top-10-by-memory. Never read /proc/PID/cmdline or environ — argv_guard_test.go fails the build if either string appears.
