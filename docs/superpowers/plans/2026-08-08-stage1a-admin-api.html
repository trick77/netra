Stage 1A — Admin API and host UI

Make it possible to onboard a host without hand-writing SQL.

Goal
Create, rotate and delete hosts and their agent tokens over HTTP, and from a minimal local web page, replacing the psql hand-insert that is the only path today.
Architecture
Admin JSON routes and a server-rendered page join the hub's existing mux. NETRA_ADMIN_TOKEN stays mandatory exactly as it is today; curl sends it as a bearer, the browser exchanges it once for a signed session cookie. No new listener, no frontend toolchain, no new environment variable.
Stack
Go 1.22 method routing, html/template + embed, pgx, TimescaleDB. No new dependencies.
Base
865a12f on master; branch worktree-admin-api-1a
Spec
docs/superpowers/specs/2026-08-07-netra-design.md §8 — authoritative

Context

auth.Mint has no non-test callers. NETRA_ADMIN_TOKEN is required at hub startup and consumed by nothing. Adding a host today means computing a SHA-256 hash by hand and inserting it with psql, then pasting the plaintext into setup-agent.sh --token. That works and it is not a product.

Everything else in Stage 1 — the remaining schema, thirteen collectors, the read API — is easier to build and test once hosts can be created over HTTP. That is why the plan puts this small piece first.

Two decisions were taken before this plan was written. The operator wants tokens minted in a UI, not by curl; and the admin token stays required, including locally — an unauthenticated admin API was considered and rejected as the riskier default, even behind a loopback binding. Both are reflected below.

Global constraints

From the phase 1 plan's "Global Constraints" and the deployment work. The ones this stage can violate:

  • Absent values are NULL, never 0. A host created with no site has site_id NULL, not 0.
  • Metric tables reference integer surrogate ids, never strings. Deleting and recreating a host must not be a way to "rename" one.
  • The plaintext token is shown exactly once and never recoverable. A lost create response is fixed by rotation, never by reading the hash.
  • Only /api/agent/ is internet-routed (Traefik PathPrefix in compose.yaml). Everything added here must live outside that prefix.
  • TDD, conventional commits, .yaml never .yml, English only, CGO_ENABLED=0 for shipped binaries.
  • Integration tests need -p 1 — store.OpenTest drops the shared public schema, so parallel package binaries race.
  • Patch coverage gate is 75% and hack/patch-coverage.sh excludes cmd/. Every error branch needs an exercised test; keep main.go wiring thin.

Three findings that shaped this plan

1. Exposure is already solved — no second listener

There is one listener and one mux today (internal/hub/httpapi/router.go, NETRA_LISTEN_ADDR=:8080). The concern was that unauthenticated host-creation on that mux would publish token minting to the internet. It does not, because compose.yaml already constrains both ends:

ports:
  - "127.0.0.1:8080:8080"          # every route is loopback-only
labels:
  traefik.http.routers.netra.rule: Host(`…`) && PathPrefix(`/api/agent/`)

Traefik routes only the ingest prefix from outside. So /api/v1/* and /ui/* are unreachable off-box by construction, and admin routes join the existing mux with no split and no new port.

Do not widen that PathPrefix. The comment above it in compose.yaml says so already, and this plan is the reason it was written. Widening it publishes host creation and token minting with no other visible change.

Consequence to accept: the UI is reachable only on the hub host itself. From a laptop that means an SSH tunnel (ssh -L 8080:127.0.0.1:8080 hub). That follows directly from "no auth" and is not changed here.

2. tokens allows multiple live rows per host

CREATE TABLE IF NOT EXISTS tokens (
    id           INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    host_id      INTEGER NOT NULL REFERENCES hosts (id) ON DELETE CASCADE,
    token_hash   BYTEA NOT NULL UNIQUE,
    created_at   TIMESTAMPTZ NOT NULL DEFAULT now(),
    last_used_at TIMESTAMPTZ
);

There is no unique constraint on host_id. A rotation that only inserts leaves the previous token valid — silently, with no symptom, until someone notices a revoked agent still posting. Rotation therefore deletes and inserts in one transaction, and its test asserts both halves.

3. sites already carries lat/lon — no schema work

sites has latitude, longitude, country_code and timezone in 0001_init.sql:21-32. PATCH /api/v1/sites needs no migration and this stage has no dependency on 1B. The rule that a manually set lat/lon is never overwritten by a geocode result is enforced in the handler, not the schema.

Nothing existing is removed

NETRA_ADMIN_TOKEN stays mandatory, and compose.yaml's comment about it stays true. config.go:33-35 fails startup without the token, and compose.yaml:37-38 documents that as deliberate: "the hub refuses to start without it rather than serving an unauthenticated admin API." An earlier draft of this stage relaxed both for local use. That was rejected: the loopback binding is a second line of defence, not a reason to drop the first. No config change, no new environment variable, and AuthMode is not introduced — the phase-2 OIDC switch can add it when there is a second mode to switch to.

The cost lands on the UI instead. A browser cannot attach Authorization: Bearer to a form post, so the page needs its own way to carry the token — Task 1.

    // sessionKey derives the cookie-signing key from the admin token, so there is
// no second secret to configure and changing NETRA_ADMIN_TOKEN invalidates
// every session that was issued under the old one.
func sessionKey(adminToken string) []byte {
	sum := sha256.Sum256([]byte("netra-session\x00" + adminToken))
	return sum[:]
}

func sign(key []byte, expiry int64) string {
	m := hmac.New(sha256.New, key)
	fmt.Fprintf(m, "%d", expiry)
	return base64.RawURLEncoding.EncodeToString(m.Sum(nil))
}

func newSessionCookie(adminToken string, now time.Time) *http.Cookie {
	expiry := now.Add(sessionTTL).Unix()
	return &http.Cookie{
		Name:  sessionCookieName,
		Value: fmt.Sprintf("%d.%s", expiry, sign(sessionKey(adminToken), expiry)),
		Path:  "/",
		// The UI is served over plain HTTP on loopback, so Secure would make
		// the cookie undeliverable. HttpOnly keeps it out of script, and
		// SameSite=Strict is what stops a cross-site form post from reaching
		// the state-changing routes with a live session attached.
		HttpOnly: true,
		SameSite: http.SameSiteStrictMode,
		Expires:  now.Add(sessionTTL),
	}
}

func validSession(adminToken string, r *http.Request, now time.Time) bool {
	c, err := r.Cookie(sessionCookieName)
	if err != nil {
		return false
	}
	rawExpiry, mac, ok := strings.Cut(c.Value, ".")
	if !ok {
		return false
	}
	expiry, err := strconv.ParseInt(rawExpiry, 10, 64)
	if err != nil {
		return false
	}
	// Verify before trusting the expiry: the MAC is what makes it unforgeable.
	if subtle.ConstantTimeCompare([]byte(mac), []byte(sign(sessionKey(adminToken), expiry))) != 1 {
		return false
	}
	return now.Unix() < expiry
}

    SameSite=Strict is doing real work here: with it, this stage needs no separate CSRF token for the form posts in Task 6.

    // ErrNotFound is returned when an operation names a host that does not exist.
// It is separate from a database failure so the handler can answer 404 rather
// than 500.
var ErrNotFound = errors.New("not found")

// RotateToken mints a replacement token and revokes every previous one.
//
// Delete and insert share a transaction because tokens has no UNIQUE
// constraint on host_id: an insert-only rotation would leave the old token
// live, and a delete that committed alone would lock the agent out with no
// replacement. Neither half is correct without the other.
func (s *Service) RotateToken(ctx context.Context, hostID int32) (string, error) {
	tx, err := s.pool.Begin(ctx)
	if err != nil {
		return "", fmt.Errorf("begin: %w", err)
	}
	defer func() { _ = tx.Rollback(ctx) }()

	var exists bool
	if err := tx.QueryRow(ctx,
		`SELECT EXISTS (SELECT 1 FROM hosts WHERE id = $1)`, hostID).Scan(&exists); err != nil {
		return "", fmt.Errorf("check host: %w", err)
	}
	if !exists {
		return "", ErrNotFound
	}

	plain, hash, err := auth.Mint()
	if err != nil {
		return "", fmt.Errorf("mint: %w", err)
	}

	if _, err := tx.Exec(ctx, `DELETE FROM tokens WHERE host_id = $1`, hostID); err != nil {
		return "", fmt.Errorf("revoke old tokens: %w", err)
	}
	if _, err := tx.Exec(ctx,
		`INSERT INTO tokens (host_id, token_hash) VALUES ($1, $2)`, hostID, hash); err != nil {
		return "", fmt.Errorf("insert token: %w", err)
	}

	if err := tx.Commit(ctx); err != nil {
		return "", fmt.Errorf("commit: %w", err)
	}
	return plain, nil
}

    CreateHost follows the same shape: one transaction, INSERT INTO hosts … RETURNING id, then the token insert, so a host is never created without a token. DeleteHost uses DELETE FROM hosts WHERE id = $1 and returns ErrNotFound on a zero RowsAffected; tokens go with it via ON DELETE CASCADE. ListHosts left-joins host_current for last_seen and never touches a hypertable.

    // RequireAdmin gates the admin API and the UI on NETRA_ADMIN_TOKEN, presented
// either as a bearer header or as a session cookie minted from the same token.
//
// redirectToLogin is set for the UI mount only. An API client wants a 401 it
// can act on; a browser wants somewhere to go.
func RequireAdmin(token string, redirectToLogin bool, next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		bearer := strings.TrimPrefix(r.Header.Get("Authorization"), "Bearer ")
		ok := subtle.ConstantTimeCompare([]byte(bearer), []byte(token)) == 1 ||
			validSession(token, r, time.Now())
		if ok {
			next.ServeHTTP(w, r)
			return
		}

		w.Header().Set("Cache-Control", "no-store")
		if redirectToLogin {
			http.Redirect(w, r, "/login", http.StatusSeeOther)
			return
		}
		http.Error(w, "unauthorized", http.StatusUnauthorized)
	})
}

    Constant-time compare for the same reason auth.Authenticate uses one. The bearer check runs first so an API client never pays for a cookie parse.

	}

Verification

Beyond make check, the spec's own acceptance test for 1A is an end-to-end onboarding run:

  1. Start the hub with no NETRA_ADMIN_TOKEN. It must still refuse to start, exactly as before this stage.
  2. Open http://127.0.0.1:8080/. It must redirect to /login, not render the host list.
  3. Log in with the admin token, create host web01, copy the rendered setup-agent.sh line.
  4. Run that line on a real host. The agent posts; GET /api/v1/hosts with a bearer header shows a last_seen that advances.
  5. Rotate the host's token in the UI. The running agent starts getting 401s; re-run setup with the new token and it recovers.
  6. Change NETRA_ADMIN_TOKEN and restart. The still-open browser session must be logged out on its next request — the cookie's signing key changed with it.
  7. Grep the hub logs for both plaintexts, the agent token and the admin token. Neither may appear — not on create, not on rotate, not on login, not on the 401s.
  8. curl the admin API from another machine against the public hostname. Traefik must 404 — only /api/agent/ is routed.

Step 7 is the one most likely to be skipped and most likely to be wrong: a token that leaks into a log is as compromised as one in a cached response, and nothing in the unit tests looks at log output.

Out of scope

  • The read API (1D) — GET /api/v1/hosts/{id}/metrics and tier selection. GET /api/v1/hosts lands here only because the UI needs a list to render.
  • OIDC — phase 2. It replaces the login handler and the session-cookie source; RequireAdmin and every route behind it stay as they are. An AuthMode switch is deliberately not introduced now, when there would be only one mode to select.
  • Any design system or frontend build. The phase-2 UI owns that decision, and starting it here would prejudge it.
  • Migration checksum detection. Still open in 1B, still gated on "before the first release".
